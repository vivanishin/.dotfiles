# AGENTS.md

## What this repo is

`/home/vlad` itself is the git working tree — a dotfiles repo tracked at
`github.com/vivanishin/.dotfiles`. There is no build system, test suite, CI,
or package manifest. The "codebase" is shell config, Emacs Lisp, and tool
config files.

## Multi-repo layout via `repo`

The full environment is managed by the Android `repo` tool. The manifest lives
at `~/.repo/manifests/default.xml`. `repo sync` updates all repos at once.

Key repos in the manifest:

| Path | Remote repo | Notes |
|------|-------------|-------|
| `.` (home) | `vivanishin/.dotfiles` | this repo |
| `bin/` | `vivanishin/bin` | personal scripts; commit from inside `bin/` |
| `bin/z` | `rupa/z` | frecency jump tool; sub-repo under `bin/` |
| `.priv/` | private SSH remote | private files; gitignored in dotfiles |
| `.vim/pack/plugins/start/*` | various GitHub | vim plugins as separate repos |
| `.config/qutebrowser/solarized-everything-css/` | `alphapapa` | gitignored in dotfiles |

`bin/` and `.vim/pack/` are excluded from the dotfiles `.gitignore` — changes
there must be committed in their own repos, not from home.

## Tracked vs ignored — the gitignore is aggressive

**Tracking principle:** track a file if it contains only meaningful, hand-authored
values (i.e. the repo should be sufficient to recreate the environment on a new
host). Ignore files that are autogenerated, caches, state dumps, or
machine-specific runtime data.

Notable exclusions:
- `bin/`, `.local/`, `.cache/`, `.config/alacritty/`, `.config/git/`
- `.emacs.d/lisp/init-gnus.el` (gitignored here; it is a symlink managed by `repo` from `.priv/`)
- `.persistent_history`, `.*_history`, `.bash_history`
- `.priv/`, `.gnupg/*` (except `gpg-agent.conf`)
- Most `.config/` subdirs (only specific ones are tracked — see `.gitignore`)

When deciding whether to track a new file, apply the principle above. Verify
with `git check-ignore -v <path>` before assuming it is tracked.

## No build/test/lint steps

There are no commands to run for validation. After editing a dotfile:
1. Source the file if it's shell config (`source ~/.bashrc` or `rcre` alias)
2. Restart the relevant application if needed
3. Commit with `git add -p` and `git commit`

`git add -p` is preferred since the working tree is `$HOME` — staging
individual hunks avoids accidentally staging unrelated home-directory changes.

## Shell environment notes

- `z` (frecency jump) is sourced from `~/bin/z/z.sh`; state file `~/.z` is gitignored
- `clip` function abstracts `wl-copy` (Wayland) / `xclip` (X11)
- `e` / `ec` aliases call `emacsclient`; accepts `file:line:col` format
- `rcre` reloads `~/.bashrc` in the current shell
- Git shorthand functions: `gs`, `gl`, `gd`, `gds`, `gg`, `gsh`, `amend`, `cln`

## Setup reference

Manifest repo: `https://github.com/vivanishin/manifest`

Fresh-system bootstrap (from the manifest README):
```bash
repo init --no-clone-bundle -u git@github.com:vivanishin/manifest.git --config-name
repo sync
repo forall -c 'git checkout $REPO_RREV'
repo init --config-name
```
